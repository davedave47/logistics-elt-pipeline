# 🛵 Last-Mile Delivery Analytics: Uncovering "Spatial Blindness"

## 📌 Project Overview (Group 2)
This project implements a modern **ELT (Extract, Load, Transform)** data pipeline to analyze the hidden financial costs of "Spatial Blindness" in last-mile logistics. 

In densely populated areas like Ho Chi Minh City, traditional routing algorithms often underestimate delivery times due to complex alleyways (*hẻm*) and heavy traffic zones. This project generates synthetic telemetry data, loads it into a local Data Warehouse, and uses spatial transformations (H3 Hexagons) to calculate the **Margin Gap**—the exact dollar amount lost to these hidden delays.

## 🏗️ Architecture: The Modern Data Stack
We strictly follow an ELT approach, moving raw data into the warehouse first, then applying transformations in-database to avoid inefficient data egress.

1. **Extract / Generate:** Python & `Faker` generate structured (CSV) and semi-structured (JSON) logistics data simulating HCMC traffic patterns.
2. **Load (Data Lake $\rightarrow$ Warehouse):** DuckDB natively ingests the raw files from the Data Lake into staging tables using high-performance C++ readers.
3. **Transform:** `dbt` (Data Build Tool) unpacks the JSON, calculates time variances, and snaps GPS coordinates into **H3 Hexagon** grids to aggregate profitability.

## 🚀 Setup & Installation

**1. Clone the repository and navigate to the root folder:**
```bash
git clone <your-repo-url>
cd last-mile-project
```

**2. Create and activate a Python Virtual Environment:**
* **Mac/Linux:**
  ```bash
  python3 -m venv venv
  source venv/bin/activate
  ```
* **Windows:**
  ```bash
  python -m venv venv
  .\venv\Scripts\activate
  ```

**3. Install Dependencies:**
```bash
pip install -r requirements.txt
```

## ⚙️ Execution Guide

### Phase 1: Populate the Data Lake
Run the data generator to create 5,000 synthetic sales orders and their corresponding driver route telemetry.
```bash
cd data_generator
python generate_data.py
```
*Verify: Check the `../data_lake/` folders to ensure the CSV and JSON files were created.*

### Phase 2: Load the Data Warehouse (EL)
Run the loader script to push the raw data into DuckDB. Notice that no transformations happen here; the semi-structured JSON is preserved as DuckDB `STRUCT` types.
```bash
cd ../loader
python load_to_duckdb.py
```
*Verify: Check the `../db/` folder for the newly created `logistics.duckdb` file.*

### Phase 3: Transform & Analyze (dbt)
*(Note: Ensure you have initialized your dbt profile to point to the `logistics.duckdb` file).*
Run the dbt models to calculate the H3 spatial grids and the financial margin gaps.
```bash
cd ../dbt_project
dbt run
```

## 📊 Data Dictionary
* **`crm_customers.csv`**: Structured dimension table of customer accounts.
* **`ecommerce_products.csv`**: Structured dimension table of the product catalog.
* **`sales_orders.json`**: Semi-structured fact table containing the shopping cart array, shipping snapshot, and the baseline revenue (shipping fee paid).
* **`delivery_telemetry.json`**: Semi-structured fact table tracking the driver's actual route. Contains running timestamps (`estimated_delivery_at` vs `actual_delivery_at`), exact HCMC GPS coordinates, and vehicle metadata.
